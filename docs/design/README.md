## Derived specifications

- [`admin-ui-spec.md`](admin-ui-spec.md) translates the approved **Admin / Manage
  Places** desktop screen into implementation requirements, component inventory,
  responsive proposals, accessibility requirements, and outstanding decisions.
- [`DESIGN.md`](DESIGN.md) defines the current visual direction and token source.
- [`wireframe-brief.md`](wireframe-brief.md) maps all confirmed version-one routes
  to adaptive large-screen templates and required UI states.
- [`route-coverage-audit.md`](route-coverage-audit.md) maps every confirmed route
  to approved evidence and prioritizes the remaining missing or partial visual
  variants.
- [`phase-0-consistency-review.md`](phase-0-consistency-review.md) records the
  final route, responsive, privacy, token, accessibility, and scope consistency
  review plus the Phase 1 handoff condition.
- [`public-ui-audit.md`](public-ui-audit.md) evaluates the existing **Home /
  Explore** screen and records the required product, privacy, routing, responsive,
  and accessibility revisions.

## Remaining design follow-up

The shared public, authentication, account, personal, contribution, moderation,
and administration systems are approved at the minimum 1024 and desktop 1440
targets. The `DESIGN.md` palette is reconciled. **TravelTrove** and its restrained
text wordmark are confirmed as the version-one identity. Phase 0 design work is
complete.

The route-by-route status and completion gate are maintained in
[`route-coverage-audit.md`](route-coverage-audit.md). Admin Places implementation
requirements remain in [`admin-ui-spec.md`](admin-ui-spec.md).
